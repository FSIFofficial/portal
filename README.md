# FSIF Portal

FSIF（未来宇宙産業フォーラム）メンバー向けポータルサイト。

| 役割 | 使うもの |
| --- | --- |
| 画面 | Next.js（静的書き出し）→ **GitHub Pages** |
| 裏側（API） | **Google Apps Script**（コードは**このリポジトリには置かず**、管理者が別途保管） |
| データ | **Googleスプレッドシート**（GASが管理。**直接編集しない**） |
| 資料 | **Google Drive**（資料館からリンクで開く／ダウンロード） |
| ログイン | **Googleでログイン**（Google Identity Services） |

ツール・資料・お知らせの追加や変更はポータルの「管理画面」から、アカウント・ロール（権限）は **FSIF Access Manager**（`/access/`）から行います。

---

## 画面と権限

- **ホーム / ツール / 資料館 / 検索**：ログインした人が、自分のロールで見られるものだけ表示されます。
  - ツールの☆でお気に入りに登録すると、ホームの先頭に表示されます（人ごと）。
  - 資料館は「よく見られている順」でも並べられます。
  - 前回ログインしてから追加・更新されたツール・資料・リンクには「NEW」が付き、メニューに件数が出ます。開くとそのNEWは消えます。サイドメニューの「すべて既読にする」でまとめて消すこともできます（何もしなくても、次の日にポータルを開くと入れ替わります）。
- **お知らせ**：「確認を求める」にしたお知らせは「確認しました」を押すまで消えず、管理画面で誰が確認したかを見られます。
- **資料のプレビュー**：資料館の「プレビュー」で、Driveの資料をポータルの中で表示できます（閲覧権限のあるGoogleアカウントでブラウザにログインしている必要があります）。
- **管理画面の使い方ガイド**：「管理画面 > 使い方ガイド」に、自分の権限でできる作業の手順がまとまっています。
- **ゴミ箱**：削除したツール・資料・お知らせ・アカウントは30日間ゴミ箱に残り、元に戻せます。
- **ホーム画面に追加**：右上のメニュー →「ホーム画面に追加」から、アプリのようにアイコンで開けるようにできます。
- **リンク集**：よく使うWebサイトやフォームへのリンクを、カテゴリごとにまとめて表示します。各リンクはURLをコピーでき、☆を付けるとホームの「お気に入りのリンク」に表示されます。サイトのアイコンは自動で取得します（Google → DuckDuckGo → サイト自身の順に試し、取れなければ頭文字）。社内サイトなどで出ないときは、リンク管理でアイコン画像を設定できます。「リンクの追加・編集」権限を持つ人（標準では掲載担当者）が管理画面の「リンク管理」で編集します。
- **お知らせ一覧**：閉じたお知らせや掲載が終わったお知らせも読み返せます。確認が必要なお知らせはここからも「確認しました」を押せます。
- **表示モード**：右上のメニューで「ライト／ダーク／端末に合わせる」を選べます（このブラウザに保存）。
- **検索**：ツール・資料・リンクの名前や説明に加え、Google Driveの全文検索で資料の本文からも探します（GASを実行しているアカウントが見られるファイルが対象）。
- **プライバシーポリシー・利用規約**：`/privacy/`・`/terms/`（ログインなしで読める）。問い合わせ先は「ヘルプ・問い合わせ」に誘導しているので、窓口を変えるときはヘルプを編集する
- **ヘルプ・問い合わせ**：問い合わせ先とよくある質問。「お知らせ」を編集できる人が内容を編集できます。
- **管理画面**：ロールに付けた権限に応じてメニューが出ます（ツール・資料・お知らせ・ヘルプ編集・アカウント・ロール・設定・利用状況・変更履歴・バージョン確認）。

| ロール（初期） | できること |
| --- | --- |
| 全権管理者 `superadmin` | すべて。**アカウント追加・ロール作成・権限設定・設定変更**はこのロールだけ |
| 掲載担当者 `editor` | ツール・資料・お知らせの編集、変更履歴の閲覧 |
| メンバー `member` | 閲覧のみ |

全権管理者は FSIF Access Manager（`/access/`）の「ポータルのロール」で新しいロール（例：契約担当、広報チーム）を作り、
「メンバー」でユーザーに割り当てます（ポータルの管理画面の「アカウント」「ロールと権限」は Access Manager への案内です）。ツール・資料・お知らせの「公開範囲」でロールを選ぶと、
そのロールを持つ人にだけ表示されます（未選択なら全員に表示）。

閲覧範囲のチェックはGAS側（サーバー）で行っているので、権限のないデータはブラウザに送られません。

> 資料館の資料はGoogle Driveにあります。ポータルの公開範囲とは別に、**Drive側の共有設定**も必要です。
> 資料ごとに「Driveの共有を公開範囲に合わせる」をオンにすると、GASが閲覧者を自動で追加・解除します（ポータルが追加した相手だけを管理し、手動の共有には触れません）。
> 「リンクを知っている全員」で共有されている資料は管理画面に警告が出て、ボタンひとつでリンク共有をオフにできます。

### ログイン

Googleでログインすると、GASが専用のセッションを発行します。前回表示したデータをブラウザに残しておき、次に開いたときはまずそれを表示してから最新に入れ替えます（ログアウトすると消えます）。操作がなければ6時間、最長でも7日でもう一度ログインが必要です（別のタブでもログインしたままになります）。
アカウントの無効化やロールの変更は、次の操作からすぐに反映されます。

## アクセス権限管理（/access/）

FSIFのツール（kodama・quiz manager など）を「誰が使えるか」「ツールの中でどの役割か」をまとめて管理する画面です。
ポータルと同じサイトの `/access/`（本番は `https://admin.fsif.jp/access/`）で動きます。

- **使える人**：ポータルの**全権管理者だけ**。ログインはポータルと共通（ポータルでログインしていればそのまま開ける）
- **メンバー**：FSIFメンバーはここで追加・管理します。追加するとポータルのアカウントも作られ、ポータルに入れるようになります。
  退会にするとポータルのアカウントを無効にし、退会から戻すと有効に戻します。メンバーの編集でポータルのロールも割り当てます（複数可。追加のメールアドレスのアカウントにも同じロール）。
  大人数は「一括追加」で、表計算ソフトから名前とメールアドレスを貼り付けます。「しばらくログインなし」で、90日以上ポータルにログインしていない人を絞り込めます
- **ポータルのロール**：ポータルのロールの作成・編集・削除と、できる操作の設定（ポータルの管理画面から移したもの）。正本はこれまでどおりポータルの GAS で、Access Manager はポータルの API を通して書き換えます
  既存のアカウントは「メンバー > ポータルから取り込む」でまとめて取り込めます
- **ツール**：一覧はポータルの「ツール」から同期します（「停止中」は無効扱い）。ツールの中の役割（閲覧者・編集者など）と連携状態は、この画面の「ツール・同期 > 役割・連携を設定」で定義します
- **組織上の役割**：代表（1人。全体を管理）・事業部長（部署ごと）・団体垢（団体・部署で共用するアカウント。ツール権限は持てるが、代表・事業部長・申請の承認者にはなれない）。代表は「管理権限設定」で任命・変更・解除します
- **部署**：階層で登録できます（親の部署を選ぶ）。事業部長は配下の部署のメンバーも管理でき、上の部署に設定した申請先・管理範囲は配下の部署にも効きます。テンプレート（自動付与）は部署ごとで、親から引き継ぎません
- **メールアドレス**：1人に複数登録できます（別の Google アカウントでもログインする人向け）。どのアドレスでも同じ権限になり、ポータルのアカウントもアドレスごとに作ります
- **付与の仕組み**：部署・役職ごとのテンプレートによる自動付与、手動のON/OFF、申請・承認、変更履歴（画面の中に説明があります）
- **各ツールからの問い合わせ**：保存のたびに「メンバー×ツールの利用可否と役割」（実効権限）を計算して GAS に保存します。
  各ツールの GAS は、権限管理の GAS に次のように問い合わせます（キーはツールごと）

  ```js
  // ツールの GAS 側（利用者の Google の ID トークンは、ツールの GAS で検証してから email を渡す）
  const res = UrlFetchApp.fetch(ACCESS_GAS_URL, {
    method: 'post',
    contentType: 'text/plain',
    payload: JSON.stringify({ action: 'checkAccess', payload: { toolId: 'ポータルのツールID', key: 'ツールのキー', email } }),
  })
  // → { ok: true, data: { allowed: true, roleKey: 'editor', roleLabel: '編集者', rank: 2, name: '…', reason: '' } }
  ```

  `listAccess`（`{ toolId, key }`）で、そのツールを使える人の一覧も取れます。

### セットアップ

1. 権限管理用のスプレッドシートを新しく作り（管理メンバーだけで共有）、「拡張機能 > Apps Script」に、管理者から受け取った
   アクセス権限管理の `Code.gs` と `appsscript.json` を貼る（**GitHubには置きません**。ポータルのGASとは別のプロジェクト）
2. スクリプト プロパティに `PORTAL_GAS_URL`（ポータルのGASのURL）を追加し、関数 `setup` を実行
3. 「デプロイ > 新しいデプロイ > ウェブアプリ」（実行：自分／アクセス：全員）で発行された URL を、
   GitHub の Variables に `ACCESS_GAS_URL` として登録し、`main` に push（またはデプロイを再実行）
4. ポータルの「ツール管理」でツールを追加：URL `https://admin.fsif.jp/access/`、公開範囲は全権管理者
5. 画面で「ツール・同期 > ポータルから同期」→ 各ツールの役割を定義 →「所属・自動付与」で部署とテンプレート →「メンバー」で取り込み・所属を設定
6. ツールを連携するときは、GASエディタで関数 `issueToolKeys` を実行し、ログに出たツールIDとキーをそのツールの GAS に設定する

> データは「データA」「データB」「データC」のどれかに入ります（保存のたびに、いまの版でも1つ前の版でもないシートへ書き、書けたことを確かめてから切り替える）。シートは直接編集しないでください。
> 直前の保存を取り消すときは GAS エディタで `undoLastSave` を実行します。スクリプトプロパティ `BACKUP_FOLDER_ID` を設定して `installDailyBackup` を一度実行すると、毎日の控え（JSON、新しい30個）がドライブに残り、`restoreFromBackup` で戻せます。
> ログインの確認は、受け取ったセッションでポータルの GAS の `bootstrap` を呼んで行います（5分キャッシュ）。
> `ACCESS_GAS_URL` が未設定のまま公開すると、`/access/` は「未設定」の案内を出します（ポータル自体には影響しません）。
> ポータルがデモモードのとき（手元の `pnpm dev` など）は、`/access/` もブラウザ内のサンプルデータで動きます。

## 広報管理（/kouhou/）

X・Instagram・Discord の投稿を、企画から下書き・承認・予約・公開記録・分析までまとめて管理する画面です。
ポータルと同じサイトの `/kouhou/`（本番は `https://admin.fsif.jp/kouhou/`）で動きます。

- **画面**：ダッシュボード / カレンダー（月・週・日）/ 投稿一覧 / 承認待ち（内容・日時の2段階承認）/ 企画スペース / 繰り返し予約 /
  素材・テンプレート（背景テンプレートに文字を入れて投稿画像を作るエディタ付き）/ 投稿分析 / 管理者設定（ブランド・アカウント・利用者・緊急停止など）
- **本番**：広報管理用の GAS（ポータルの GAS とは別）にデータを保存し、X API と Discord Bot で実際に送信します。
  GitHub の Variables に `KOUHOU_GAS_URL` が無いうちは、`/kouhou/` は「準備中」の案内を出します（本番でサンプルデータは見せません）
- **デモ**（手元の `pnpm dev`・CI）：ブラウザ内のサンプルデータで動き、画面上部に「デモ」の帯が出ます。右上の「デモ操作」で、ユーザーの切り替え・基準日時を進める（予約投稿が配信される）・競合や配信失敗の再現・サンプルデータの初期化ができます
- **ログイン**：ポータルと共通。ポータルにログインしている人のうち、**アクセス権限管理（/access/）で「広報管理」の権限を付与された人**だけが使えます
- **利用者**：アクセス権限管理で管理します（広報管理の中では追加・レベル変更・管理者の付け外しはしません）。役割キーを次のように読み替えます
  | 役割キー | 広報管理での扱い |
  | --- | --- |
  | `level1` | レベル①：原稿の作成。内容は承認が必要 |
  | `level2` | レベル②：定期投稿の内容は自動承認 |
  | `level3` | レベル③：内容は自動承認。承認者になれる |
  | `admin` | 管理者：レベル③＋管理者設定（アカウント接続・権限・緊急停止） |

  付与された人は広報管理を開いたときに自動で登録され（役割の変更も反映）、1時間ごとの同期で権限が外れた人は「利用停止」になります（投稿の履歴を残すため削除はしません）。
  SNSアカウントごとの閲覧・作成・編集・承認は、広報管理の「管理者設定 > 権限」で調整します（新しく登録された人は全アカウントの閲覧・作成・編集ができ、レベル③以上は承認もできる状態から始まります）
- **送信**：「予約を確定」した投稿は、GAS の時間トリガー（5分ごと）が予定時刻を過ぎたものから送信します（最大5分ほど遅れます）
  - X：本文と画像（4枚まで・各5MBまで）。アカウントごとに「Xと接続」でトークンを登録
  - Discord：本文（2000文字まで）と画像。Bot がチャンネルに送信
  - Instagram：自動送信は**未対応**（「手動投稿の記録」で公開URLを記録して管理）。予約の確定もできません
  - 画像テンプレートから作った画像は、保存のときに PNG に書き出して Google Drive に保存し、それを送ります
  - 同じ投稿を二重に送らないよう、送信できた時点で GAS に印を付けます。送信に失敗した投稿は「投稿失敗」になり、通知されます
- **分析**：X は X API の `public_metrics`（表示回数・いいね・返信・リポスト＋引用）、Discord はリアクション数・スレッドの返信数を、取得予定時刻を過ぎた最初の定期処理で取得します
  （X の指標の取得には、投稿の読み取りができる X API のプランが必要です。取れなかった計測点は「取得失敗」になります）
- **通知**：承認依頼・保留・投稿失敗・公開などを、「管理者設定 > Discord通知」で選んだチャンネルに Bot が送ります（メンションは `<@&ロールID>` など）
- ポータルの「ツール管理」でツールを追加するときは、URL に `https://admin.fsif.jp/kouhou/` を入れます
- 投稿詳細の URL は `/kouhou/posts/detail/?id=投稿ID` です（静的書き出しのため、投稿IDをパスではなくクエリで渡しています）

### 仕組み

- 画面の操作（作成・承認・予約・管理者設定など）は、すべて `lib/kouhou/domain/` の関数で行います。本番では、画面がまず手元で試して（入力ミスはその場で表示）、
  通ればコマンド名と引数を GAS に送り、**GAS が同じ関数を保存済みのデータに実行した結果を正とします**（権限の判定もサーバー側で行われる）
- GAS 用には `node scripts/build-kouhou-gas.mjs` で `lib/kouhou/domain/` を1ファイル `gas/kouhou/Domain.gs` にまとめます。
  **`lib/kouhou/domain/` を変えたら、これを実行して GAS の Domain.gs を貼り替えてください**（GAS の版名を変えたときは `lib/kouhou/live.ts` の `EXPECTED_KOUHOU_GAS_VERSION` も合わせる）
- データは GAS のスプレッドシートの「State」シートに JSON で保存します（直接編集しない）。送信・接続の記録は「Log」シートに残ります。画像は GAS の Drive フォルダに保存します
- 画面は60秒ごと（とタブに戻ったとき）に最新を読み込みます

### 本番のセットアップ

1. 広報管理用のスプレッドシートを新しく作り（管理メンバーだけで共有）、「拡張機能 > Apps Script」に、管理者から受け取った広報管理の
   `Code.gs`・`Domain.gs`・`appsscript.json` を貼る（**GitHubには置きません**。ポータル・アクセス権限管理の GAS とは別のプロジェクト）
2. スクリプト プロパティを追加：
   | プロパティ | 値 |
   | --- | --- |
   | `PORTAL_GAS_URL` | ポータルの GAS のウェブアプリ URL |
   | `ACCESS_GAS_URL` | アクセス権限管理の GAS のウェブアプリ URL |
   | `ACCESS_TOOL_ID` / `ACCESS_TOOL_KEY` | アクセス権限管理の GAS で `issueToolKeys` を実行して出た、広報管理のツールIDとキー |
   | `X_API_KEY` / `X_API_SECRET` | X Developer Portal のアプリの API Key / API Key Secret |
   | `DISCORD_BOT_TOKEN` | Discord Bot のトークン |
   | `SITE_URL` | （省略可）通知に載せるリンクの先。既定は `https://admin.fsif.jp` |
3. アクセス権限管理の「ツール・同期」で広報管理の役割（`level1`・`level2`・`level3`・`admin`）を定義し、最初の管理者に `admin` を付与しておく
4. 関数 `setup` を実行して権限を承認する（シート・画像フォルダ・5分ごとのトリガーが作られ、アクセス権限管理から利用者を取り込みます）
5. 「デプロイ > 新しいデプロイ > ウェブアプリ」（実行：自分／アクセス：全員）で発行された URL を、GitHub の Variables に `KOUHOU_GAS_URL` として登録し、`main` に push（またはデプロイを再実行）
6. **X**：Developer Portal でアプリの権限を **Read and write** にし、投稿する各アカウントで Access Token / Secret を発行 → 広報管理の「管理者設定 > SNSアカウント」でアカウントを追加して「Xと接続」に入力
7. **Discord**：Developer Portal で Bot を作り、サーバーに招待（権限：チャンネルを見る・メッセージを送信・ファイルを添付・メッセージ履歴を読む）→
   「管理者設定 > Discord」でサーバーIDを入れて「Discordからチャンネルを取得」→ 投稿に使うチャンネルを「投稿可能」に、「Discord通知」で通知先を選んで「テスト通知を送る」
8. 必要なら「管理者設定 > 権限」で、アカウントごとの権限（閲覧・作成・編集・承認）を調整する

> X API の利用には X Developer Portal での契約（プラン）が必要です。投稿の数・指標の読み取りの上限はプランによって違います。
> トークンは GAS のスクリプト プロパティにだけ保存され、画面やスプレッドシートには出ません。

## セットアップ手順

### 1. スプレッドシートとGAS

1. Googleスプレッドシートを新規作成する（名前は自由。例：`FSIF Portal DB`）
2. メニュー「拡張機能 > Apps Script」を開く
3. 管理者から受け取った `Code.gs` の中身をエディタの `コード.gs` に貼り付ける
4. 「プロジェクトの設定（⚙）」で「`appsscript.json` マニフェスト ファイルをエディタで表示する」をオンにし、受け取った `appsscript.json` の中身で上書きする
5. 「プロジェクトの設定 > スクリプト プロパティ」に追加：
   | プロパティ | 値 |
   | --- | --- |
   | `GOOGLE_CLIENT_ID` | 手順2で作るクライアントID |
   | `SUPER_ADMIN_EMAILS` | 最初の全権管理者のGmail（カンマ区切りで複数可） |
6. エディタで関数 `setup` を選んで「実行」→ 権限を承認する。シート（Users / Roles / Tools / Documents / Announcements / Settings / Logs）と初期データが作られます
7. 「デプロイ > 新しいデプロイ > 種類：ウェブアプリ」
   - 次のユーザーとして実行：**自分**（Driveの共有同期・アップロード・バックアップは、この人の権限で行われます）
   - アクセスできるユーザー：**全員**
   - 発行された `https://script.google.com/macros/s/…/exec` のURLを控える

> ログインしていない人や登録されていない人からのリクエストは、GAS側でIDトークンを検証して拒否します。
> コードを更新したときは「デプロイを管理 > 編集 > バージョン：新バージョン」で同じURLのまま更新できます。

### 2. Googleログイン用のクライアントID

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成（GASと同じアカウントでOK）
2. 「APIとサービス > OAuth同意画面」を設定（外部 / 内部はご利用のアカウントに合わせて）
   - 「外部」の場合は、公開ステータスを「テスト」から**「本番環境」に公開**しておく（テスト中は登録したテストユーザーしかログインできない）。
     使うのはメールアドレスとプロフィールだけなので、Google の審査は不要です
   - 「ブランディング」には、アプリのホームページ `https://admin.fsif.jp/`、プライバシーポリシー `https://admin.fsif.jp/privacy/`、利用規約 `https://admin.fsif.jp/terms/` を登録する（どちらもログインなしで読めるページ。ログイン画面とヘルプページからもリンクしている）
   - このクライアントIDは、quiz manager・イベント特設ページ作成の管理画面のGoogleログインでも共通で使う（各ツールのドメインを下の「生成元」に追加する）
3. 「認証情報 > 認証情報を作成 > OAuthクライアントID」
   - 種類：**ウェブアプリケーション**
   - 承認済みの JavaScript 生成元：`https://admin.fsif.jp`（ローカル確認用に `http://localhost:3000` も追加可）
4. 発行されたクライアントIDを、GASのスクリプトプロパティ `GOOGLE_CLIENT_ID` と、次のGitHub変数の両方に設定

### 3. GitHub Pages

1. リポジトリの「Settings > Pages > Build and deployment > Source」を **GitHub Actions** にする
2. 「Settings > Secrets and variables > Actions > Variables」に追加：
   | 変数 | 値 |
   | --- | --- |
   | `GAS_URL` | 手順1-7のウェブアプリURL |
   | `GOOGLE_CLIENT_ID` | 手順2のクライアントID |

   **Secrets ではなく Variables タブ** に登録してください。未設定のままだと公開処理がエラーで止まります（本番サイトがデモ画面になるのを防ぐため）。デモとして公開したい場合だけ `ALLOW_DEMO` = `true` を追加します。
3. 独自ドメイン `admin.fsif.jp` で公開する設定：
   - DNS（fsif.jp を管理しているサービス）に CNAME レコードを追加：名前 `admin` → 値 `fsifofficial.github.io`
   - 「Settings > Pages > Custom domain」に `admin.fsif.jp` を入れて Save。DNSの確認が通ったら **Enforce HTTPS** にチェック
   - 公開処理はドメインに合わせて自動でパスを切り替えます（独自ドメインでは `/portal` が付きません）
4. `main` ブランチにpushすると `.github/workflows/deploy.yml` が動き、`https://admin.fsif.jp/` に公開されます

### 4. 初回ログイン後

`SUPER_ADMIN_EMAILS` のアカウントでログイン →
1. FSIF Access Manager（`/access/`）の「ポータルのロール」で必要なロールを作成
2. Access Manager の「メンバー」でメンバーを追加してロールを割り当て（ポータルのアカウントが作られる）
3. ポータルの管理画面の「ツール管理」「資料管理」「お知らせ」で掲載内容を登録

### チェック

プルリクエストを作ると `.github/workflows/ci.yml` で型チェック・ビルド・画面の自動テスト（Playwright、デモモード）が動きます。`main` に入ると `deploy.yml` で公開されます。

ダークモードの配色は `scripts/gen-dark-css.mjs` が画面で使っている色から自動で作ります（`pnpm build` / `pnpm dev` のたびに `app/dark.css` を生成）。

手元で画面の自動テストを動かす場合：

```bash
NEXT_PUBLIC_BASE_PATH=/portal pnpm build
pnpm exec playwright install chromium
pnpm test:e2e
```

テストは `tests/e2e/` にあります。`a11y.spec.ts` は axe で主な画面をライト・ダークの両方で点検し、色のコントラスト不足や名前のないボタンなど重大な問題がないことを確かめます。

### 同時編集

複数人が同時に管理画面を使っても、データが壊れることはありません（GASが書き込みを1件ずつ順番に処理します）。
同じ項目を2人が同時に編集した場合は、**後から保存した人の保存が止まり**「他の人が先に更新しました」と表示されます（先に保存した人の変更は上書きされません）。最新の内容が自動で読み込まれるので、確認してから編集し直してください。
ツールの並べ替え中に他の人がツールを変更した場合も同様です。ロール・設定・ヘルプは後から保存した内容が優先されます。

### GASの更新手順

1. 新しい `Code.gs`（と `appsscript.json`）をエディタに貼り付けて保存
2. 関数 `setup` を実行（追加された列やシートが作られます。既存データは消えません。新しい権限の承認を求められたら許可する）
3. 「デプロイを管理 > 編集 > バージョン：新バージョン」でデプロイ
4. ポータルの「管理画面 > バージョン確認」ですべて ✓ になることを確認し、「動作チェックを実行」で各機能が本番で動くか確かめる（版がずれていると、管理者には画面上部に赤い帯が出ます）

ポータル名・ロゴ・メインカラーは「管理画面 > 設定 > ポータル名・ロゴ・色」で変更できます。
毎朝7時ごろの自動処理（掲載開始日のお知らせのDiscord通知・30日を過ぎたゴミ箱の整理）は `setup()` を実行すると登録されます。
Discordへの新着通知は「管理画面 > 設定 > Discordへの新着通知」にWebhook URLを登録します（公開範囲が「全員」の資料・お知らせを新しく追加したときだけ投稿。限定公開のものは投稿しません）。
権限変更の通知メール（全権管理者の追加・解除、ロールの権限変更、未登録アカウントのログイン設定の変更をすぐに全権管理者へ知らせる）は「管理画面 > 設定」でオン・オフできます（初期状態はオン）。
エラー通知メール（想定外のエラーがあった日だけ、毎朝 全権管理者に送信）は「管理画面 > 設定 > エラー通知メール」でオンにします。
自動バックアップを使う場合は「管理画面 > 設定 > バックアップ」でオンにします（毎週月曜4時ごろ、新しい10個を保持）。

### GASコードの扱い

- GASコード（`Code.gs` / `appsscript.json`）と組織の内部データは **GitHubに上げません**。`gas/` フォルダは `.gitignore` 済みです。
- GASコードの1行目に版名 `GAS_VERSION` があります。画面側の期待値は `lib/config.ts` の `EXPECTED_GAS_VERSION` です。
- 「管理画面 > バージョン確認」で、版名・シートの列構成・スクリプトプロパティが合っているかを確認できます。GASのデータ形式を変えたら両方の版名を上げてください。

項目を追加するときは `lib/types.ts` とGASコードの `SCHEMA` を両方更新してください。シートの列は位置で読むので、新しい項目は **各シートの `fields` の末尾に追加** し、`setup()` を再実行してヘッダー行を更新してください。
